# Phase 31.9 — Reconnect Upload-Offer

> **Agent-Attach:** Diese Datei (nicht Archiv/ganzen Plan).
> Regeln: `@AGENTS.md` · Index: `@docs/IMPLEMENTATION_PLAN.md` · Kontext 31.x: `@docs/phases/ARCHIVE.md`

**Status:** ✅ Erledigt  
**Abhängigkeiten:** 31.3 (Badge / pending count), 31.6 (Bulk-Scan + Confirm)  
**Ziel:** Nach **stabilem** SMB-Reconnect einmalig Soft-Confirm mit kompakter Pending-Liste — Einstieg in den bestehenden Bulk-Nachholen-Flow. **Kein** stiller Auto-Drain.

> Eine Agent-Session = nur 31.9. Kein AMS-Reconnect-Offer, kein Badge-Deep-Link, kein Auto-Upload.

##### Ausgangslage (Ist vor 31.9)

- Reconnect: einmaliger Toast „Server wieder online / unter Vorgänge nachholen“
- Badge an Vorgänge zählt `pending`/`failed`
- Bulk-Nachholen nur manuell unter Vorgänge (Scan → Confirm → Upload)

##### Out of Scope (31.9)

- Stiller Auto-Upload / Background-Worker / App-Restart-Drain
- Prefight-Details oder volle Liste im Soft-Confirm (bleibt Bulk-Confirm)
- AMS-Reconnect-Offer (nur SMB / `serverConnected`)
- Badge-Deep-Link / Filter-Umbau
- Phase 31.5 Extra-Files

##### Entscheidungen (31.9)

| # | Thema | Entscheidung |
|---|--------|----------------|
| 1 | Trigger | Offline→Online-Kante; Offer **armed** solange offline |
| 2 | Stabilität | 2500 ms weiterhin `connected`; bei Disconnect Timer abbrechen und wieder armieren |
| 3 | Gates | Kein Dialog bei Splash/Setup, Create busy, Append, SD-Workflow, QR busy, Loading, Upload-Slot, anderem Blocking-Dialog |
| 4 | Busy während Reconnect | Offer armed / deferred halten → zeigen sobald idle (kein Toast-Fallback) |
| 5 | Später | Nur diese Kante; Badge bleibt; erst wieder nach erneutem Offline→Online |
| 6 | Liste | Max. 3 Namen (`gast` → `base_filename` → `#id`); danach „und N weitere“ |
| 7 | Jetzt | `pendingUploadCandidates` → Scan → **direkt** `retryVorgangUploadsBulk` (kein zweiter Bulk-Confirm) |
| 8 | Replace | Soft-Confirm Toast entfernen |
| 9 | Armed | Erst bei explizitem Später/Jetzt verbrauchen — nicht beim Öffnen |
| 10 | Open-Delay | 350 ms nach Gate-Clear, bevor der Dialog mountet (Settings-Stack) |
| 11 | Dismiss-Grace | 400 ms `onOpenChange(false)` ignorieren (Spurious-Close) |
| 12 | busyRef | Nur Re-Entry-Guard — **nicht** in Post-Await-UI-Gates (Self-Deadlock) |

##### UX-Flow

```
Server offline → Offer armed
  → Reconnect
  → 2.5s stabil + idle
  → Soft-Confirm (Titel, Count, Kurzliste)
       Später → dismiss
       Jetzt → Scan → Bulk-Confirm (ready/needs/blocked) → Upload
```
